# Demo boundaries

Request intake, declared evidence, deterministic risk and audit history are available through the local API. Complete submissions enter a background review and pause for an explicit decision. The Angular dashboard still shows the bootstrap shell. Review is available through the local API and Swagger. Approved requests queue one Jira operation. The default simulation stores the ticket locally. Live Jira delivery has been tested against mocked responses only.

The dashboard uses synthetic data only. Demo personas provide no access control. Bind the API to loopback and keep the dashboard on the same machine.

Integration modes describe settings. A configured compatible LLM receives synthetic supplier facts. Without configuration the assessment shows UNAVAILABLE. Citation checks validate field names and scalar values. Human reviewers still assess the prose and reasoning. A process interruption during a model call may leave its outcome unknown. Recovery flags that call as unavailable and continues to human review. Run one application worker and retain both SQLite files for recovery. Evidence records are declarations by the requester, and the sample risk rubric is illustrative. Independent document verification and compliance decisions are outside the demo.

A lost Jira acknowledgement leaves the outcome uncertain. The dispatcher searches for the request marker, and an empty search can reflect indexing delay. A reviewer must check Jira before authorizing another create after an ambiguous outcome. See [the architecture](architecture.md).
